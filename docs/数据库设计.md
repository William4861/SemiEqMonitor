# 数据库设计（SQLite）

> **本文件与 `src/data/databasemanager.cpp` 的 `schemaStatements()` 必须保持一致** ——
> 后者是建表语句的实现来源，本文件说明设计意图与用法。
> 修改表结构时两处同时改，并在 `CHANGELOG.md` 记录。

---

## 1. 设计原则

| 原则 | 理由 |
|---|---|
| **时间统一用 ISO8601 文本** | SQLite 无原生日期类型；文本可排序、可比较、可直接阅读（`2026-09-16T14:32:11`） |
| **枚举存整数** | 与 C++ `enum class` 一一对应，避免字符串拼写错误；含义见本文第 3 节 |
| **报警的 `cleared_at` 为 NULL 表示未恢复** | 用 NULL 而不是空串，可被 `IS NULL` 索引与查询 |
| **分表而非一张大表** | 参数（高频写入）、报警（事件）、测试结果（按 Wafer 组织）访问模式差异大 |
| **关键查询建索引** | `parameter_log(param_code, recorded_at)` 与 `alarm(cleared_at, raised_at)` |

## 2. 表结构

### 2.1 `equipment` 设备

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | |
| code | TEXT | NOT NULL UNIQUE | 设备编号，如 `AOI-01` |
| model | TEXT | | 型号，如 `AOI-X500` |
| location | TEXT | | 位置，如 `SMT-1F-A线` |
| state | INTEGER | NOT NULL DEFAULT 0 | 设备状态（见 3.1） |
| created_at | TEXT | NOT NULL | 建档时间 |

### 2.2 `lot` 批次

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | |
| lot_id | TEXT | NOT NULL UNIQUE | 批次号 |
| product_model | TEXT | | 产品型号 |
| planned_wafers | INTEGER | DEFAULT 0 | 计划晶圆片数 |
| started_at / finished_at | TEXT | | 开始 / 结束时间 |

### 2.3 `wafer` 晶圆

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | |
| wafer_id | TEXT | NOT NULL | 晶圆编号 |
| lot_id | TEXT | NOT NULL | 所属批次 |
| slot | INTEGER | NOT NULL | 片号（1..25） |
| cols / rows | INTEGER | NOT NULL | Die 阵列列数 / 行数 |
| pass_count / fail_count | INTEGER | DEFAULT 0 | 良品 / 不良数（冗余，便于快速查询） |
| yield | REAL | DEFAULT 0 | 良率 = pass / (pass + fail) |
| started_at / finished_at | TEXT | | |
| — | — | UNIQUE(lot_id, wafer_id) | 同一批次内晶圆编号唯一 |

> `pass_count` / `fail_count` / `yield` 是**冗余字段**：可从 `die_result` 实时算出来，
> 但报表按 Wafer 汇总时全表扫描太慢，所以写入时一并持久化（典型空间换时间）。

### 2.4 `parameter_log` 参数采集记录（**写入最频繁**）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | |
| param_code | TEXT | NOT NULL | 采集点编码，如 `TEMP_CH1` |
| param_name | TEXT | | 中文名（冗余，方便直接出报表） |
| unit | TEXT | | 单位 |
| value | REAL | NOT NULL | 采集值 |
| recorded_at | TEXT | NOT NULL | 采集时间 |

**索引**：`idx_param_log_code_time (param_code, recorded_at)` —— 支撑"某采集点最近 N 条"这类查询。

> ⚠️ **容量注意**：8 个采集点 × 2 Hz × 24 h ≈ 138 万行/天。
> 生产系统必须做**降采样或分区**；本项目在 D9 引入"原始数据保留 N 天 + 定时清理"策略。

### 2.5 `alarm` 报警

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | |
| param_code | TEXT | | 关联采集点 |
| level | INTEGER | NOT NULL | 报警等级（见 3.2） |
| message | TEXT | | 报警描述 |
| trigger_value | REAL | | 触发时的实测值 |
| raised_at | TEXT | NOT NULL | 发生时间 |
| cleared_at | TEXT | | **NULL = 尚未恢复** |
| acknowledged | INTEGER | DEFAULT 0 | 是否已确认 |
| ack_by | TEXT | | 确认人 |

**索引**：`idx_alarm_active (cleared_at, raised_at)` —— 支撑"当前活跃报警"查询。

### 2.6 `die_result` 芯片测试结果（Wafer Map 的数据源）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | |
| wafer_id / lot_id | TEXT | NOT NULL | 所属晶圆 / 批次 |
| x / y | INTEGER | NOT NULL | Die 在晶圆上的坐标 |
| result | INTEGER | NOT NULL | 判定（见 3.3） |
| fail_code | TEXT | | 不良代码，如 `SHORT` / `OPEN` |

**索引**：`idx_die_wafer (wafer_id)` —— Wafer Map 按晶圆整批取数。

## 3. 枚举取值

### 3.1 `equipment.state`（对应 `DeviceState`）

| 值 | 含义 |
|---|---|
| 0 | Unknown 未知 |
| 1 | Idle 待机 |
| 2 | Running 运行 |
| 3 | Down 故障停机 |
| 4 | PM 预防性维护 |

### 3.2 `alarm.level`（对应 `AlarmLevel`）

| 值 | 含义 |
|---|---|
| 0 | Info 提示 |
| 1 | Warning 警告 |
| 2 | Critical 严重 |

### 3.3 `die_result.result`（对应 `DieResult`）

| 值 | 含义 |
|---|---|
| 0 | Untested 未测 |
| 1 | Pass 良品 |
| 2 | Fail 不良 |

## 4. 典型 SQL

```sql
-- ① 某采集点最近 100 条（曲线回放）
SELECT param_code, value, recorded_at
FROM parameter_log
WHERE param_code = 'TEMP_CH1'
ORDER BY id DESC
LIMIT 100;

-- ② 当前活跃报警（未恢复）
SELECT id, param_code, level, message, trigger_value, raised_at
FROM alarm
WHERE cleared_at IS NULL
ORDER BY raised_at DESC;

-- ③ 某批次的良率汇总
SELECT lot_id,
       COUNT(*)                                   AS wafers,
       SUM(pass_count)                            AS pass_dies,
       SUM(pass_count + fail_count)               AS total_dies,
       ROUND(1.0 * SUM(pass_count)
             / NULLIF(SUM(pass_count + fail_count), 0), 4) AS yield
FROM wafer
WHERE lot_id = 'L20260916'
GROUP BY lot_id;

-- ④ 不良 Top 5（Pareto 分析用）
SELECT fail_code, COUNT(*) AS cnt
FROM die_result
WHERE result = 2 AND lot_id = 'L20260916'
GROUP BY fail_code
ORDER BY cnt DESC
LIMIT 5;

-- ⑤ 某采集点在时间窗内的统计量（SPC 用）
SELECT param_code,
       COUNT(*)      AS n,
       AVG(value)    AS mean,
       MAX(value)    AS max_v,
       MIN(value)    AS min_v
FROM parameter_log
WHERE param_code = 'TEMP_CH1'
  AND recorded_at BETWEEN '2026-09-16T09:00:00' AND '2026-09-16T10:00:00';

-- ⑥ 报警持续时长（分钟）
SELECT id, message,
       ROUND((julianday(COALESCE(cleared_at, CURRENT_TIMESTAMP))
              - julianday(raised_at)) * 1440, 1) AS duration_min
FROM alarm
ORDER BY raised_at DESC;
```

> ③ 里的 `NULLIF(..., 0)` 用于避免除零 —— 与 `Wafer::yield()` 中"总数为 0 返回 0"的处理一致。

## 5. 与 C++ 层的对应

| C++ 类型 | 读写方法 |
|---|---|
| `semieq::Parameter` | `DatabaseManager::insertParameter()` / `recentParameters()` |
| `semieq::Alarm` | `DatabaseManager::insertAlarm()` / `activeAlarms()` |
| `semieq::Wafer` / `Lot` / `Die` | D9-D10 补充写入与查询 |

**连接管理**：使用**命名连接**（`QSqlDatabase::addDatabase("QSQLITE", "semieq_main")`）。
理由：避免跨线程共用一个连接句柄（Qt 的 `QSqlDatabase` 不支持跨线程使用），
后续采集线程要落库时，为它另开一个命名连接即可。
