## 二、A1 · VSCode ＋ CMake 最小可用流程（**现在就能照做**）

```
① 装扩展（终端粘这两行）
   code --install-extension ms-vscode.cpptools
   code --install-extension ms-vscode.cmake-tools

② 打开"文件夹"（不是单个 .cpp！）
   code "D:\code_work\trae_project\PreparationForInterview\CppQtProject\SemiEqMonitor"

③ 首次打开 → VSCode 底部弹出"是否配置 CMake 项目？"→ 选 Kit：
   GCC 7.3.0 mingw32        （如果没有，Ctrl+Shift+P → CMake: Scan for Kits）

④ 构建：F7   或   Ctrl+Shift+P → CMake: Build

⑤ 运行/调试：
   - 不调试直接跑 → 脚本：scripts\run.bat monitor
   - 要断点调试  → 按 F5（配置已给：.vscode/launch.json）
```

**三个按钮/快捷键**（记住这 3 个就够）：

| 操作 | 快捷键 | 等价命令 |
|---|---|---|
| 配置（读 CMakeLists） | `Ctrl+Shift+P` → CMake: Configure | `cmake -S . -B build -G Ninja ...` |
| 构建（编译链接） | **F7** | `cmake --build build` |
| 调试（跑起来+断点） | **F5** | （gdb 接管） |

> 📌 **`scripts\build.bat` 和 VSCode 的 F7 是同一件事** —— 脚本只是把"配置＋构建"两条命令＋PATH 前置打包了。

## 三、A2 · `CMakeLists.txt` 只要认识 6 个命令

| 命令 | 作用 | 本项目的例子 |
|---|---|---|
| `add_executable(名字 源文件...)` | 生成**可执行文件** | `add_executable(SemiEqMonitor ${SEMIEQ_APP_SOURCES})` |
| `add_library(名字 STATIC 源文件...)` | 生成**静态库** | `add_library(semieq_core STATIC ...)` |
| `target_link_libraries(目标 PRIVATE/PUBLIC 库...)` | **链接**库 | `target_link_libraries(SemiEqMonitor PRIVATE semieq_core Qt5::Widgets)` |
| `target_include_directories(目标 PUBLIC 路径)` | 加**头文件搜索路径** | `target_include_directories(semieq_core PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/src)` |
| `set(变量 值...)` | 定义变量/开关 | `set(CMAKE_CXX_STANDARD 11)` |
| `option(开关 说明 ON/OFF)` | 定义**可选开关** | `option(SEMIEQ_BUILD_TESTS "构建单元测试" ON)` |

**还有 4 个"看着就懂"的**：
- `find_package(Qt5 5.14 REQUIRED COMPONENTS Core Widgets Network Sql)` —— 找库
- `configure_file(输入 输出 @ONLY)` —— 生成文件（本项目用来生成 `version.h`）
- `target_compile_options(目标 PRIVATE -Wall -Wextra)` —— 编译选项
- `if(...) / endif()` —— 条件

> 📌 **为什么这个项目要拆 `semieq_core` 静态库**：主程序、模拟器、**单元测试** 都要用同一份采集/持久化代码 → 抽成库，三个目标共享。
