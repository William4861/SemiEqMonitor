# 需求说明

> 功能清单与优先级。**纪律：P0 必达、P1 尽力、P2 超期即砍** —— 绝不为了做花活而牺牲 P0。

---

## 1. 项目目标

实现一套面向半导体制造设备的**上位机监控软件**，覆盖该类岗位的核心技术点，并具备可演示的完整形态：

1. 能与设备通信并稳定采集数据（多通道 / 多线程）
2. 能实时展示与判定（曲线、表格、报警）
3. 能存储与追溯（数据库、查询、导出）
4. 能做过程质量分析（SPC、良率）
5. 能对接上层系统（MES）
6. 具备工程化形态（构建、测试、文档、版本、协作流程）

---

## 2. 干系人与场景

| 角色 | 关心什么 | 对应功能 |
|---|---|---|
| **产线操作员** | 现在设备正常吗？有没有报警？ | 实时监控、状态灯、报警列表与声光提示 |
| **工艺工程师** | 参数漂不漂？过程能力够不够？ | 实时曲线、SPC（Cpk / X-bar 控制图）、历史查询 |
| **设备工程师** | 为什么停机？什么时候的事？ | 报警记录与恢复时间、运行日志、断线记录 |
| **生产管理** | 这批良率多少？ | 良率报表、Wafer Map、CSV 导出 |
| **MES 系统** | 把批次结果给我 | 批次数据上报接口 |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| **性能** | 8 路 × 2 Hz 采集下，CPU 占用 < 5%，界面无卡顿 |
| **稳定性** | 连续运行 8 小时不崩、内存不持续增长 |
| **容错** | 设备断线、数据异常、数据库繁忙等场景不崩溃；给出可读的错误提示与日志 |
| **可维护** | 分层清晰，通信层可替换（换协议只改采集层） |
| **可复现** | 无硬件即可完整演示；他人按 README 能一次跑起来 |
| **代码规范** | 编译零警告（`-Wall -Wextra`）；命名统一；关键决策写注释说明"为什么" |

---

## 7. 明确的边界（本项目不做）

- ❌ 不做真实的运动控制与图像算法（属设备侧）
- ❌ 不做多设备集群管理
- ❌ 不追求 SECS/GEM 全协议实现
- ❌ 不做 Web 端 / 移动端
